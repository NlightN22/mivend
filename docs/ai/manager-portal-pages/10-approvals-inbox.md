# Страница: Approvals — инбокс (`/approvals`)

> Прочитай сначала `00-shared-conventions.md`.

## Назначение

Универсальный сквозной инбокс согласований — показывает **все** заявки, назначенные текущему пользователю на решение, независимо от типа заявки (корректировка цены, установка скидки, отсрочка платежа, будущие типы). Это не подраздел внутри "Скидок" — отдельный полноценный раздел меню.

## Кто видит что

- Показываются заявки, где текущий шаг цепочки согласования требует решения именно этой роли (например, Purchasing Dept Head видит все заявки, стоящие сейчас на шаге "Purchasing Dept Head", любого типа).
- У Manager/Operator здесь также может быть вкладка "My submitted requests" — заявки, которые он сам подал, чтобы отслеживать их статус (не для принятия решения, только просмотр).

Сделай концепт для роли **Purchasing Dept Head** — у него в инбоксе реальные заявки на решение.

## Структура контента

1. Заголовок "Approvals" + два таба сверху: **"Awaiting my decision"** (по умолчанию активный) и **"All requests I'm involved in"** (история).
2. **FilterBar**: select "Type" (Price adjustment / Discount grant / Credit term extension), кнопка "Reset".
3. **DataTable**, столбцы:
    - Request # / короткий ID
    - Type (бейдж-иконка типа заявки)
    - Customer
    - Requested by (менеджер-инициатор)
    - Current step (например "Step 2 of 3 — Purchasing Dept Head")
    - Submitted date
    - Действие в конце строки: кнопка "Review" → `/approvals/:id`
4. Если у заявки был факт эскалации (её передали текущему пользователю не по обычному порядку, а через ручную эскалацию) — маленькая иконка-пометка в строке с tooltip "Escalated by {initiator name}".

## Состояния

EmptyState "No requests awaiting your decision" — с дружелюбной иконкой (например, галочка/чистый инбокс), это хорошее и частое состояние, не ошибка.

## Переходы

Клик "Review" → `/approvals/:id`.
