# Страница: Orders — список (`/orders`)

> Прочитай сначала `00-shared-conventions.md`.

## Назначение

Список заказов, доступных текущему пользователю, с фильтрами. Заменяет соответствующий раздел Vendure Admin UI.

## Кто видит что (видимость по строкам — важно отразить в моковых данных)

- **Manager**: заказы только своих клиентов.
- **Operator**: заказы всех клиентов своего подразделения/точки.
- **Dept Head (Sales/Purchasing)**: заказы только своего отдела.
- **General Director, Security Officer**: все заказы компании (агрегация через центральный хаб, включая все филиалы).

Сделай HTML-концепт для роли **Operator** (видит больше одного менеджера — хорошо демонстрирует таблицу с разными клиентами/менеджерами в колонках).

## Структура контента

1. Заголовок "Orders" + счётчик "N orders".
2. **FilterBar**: текстовый поиск (по номеру заказа/имени клиента), select "Status" (New / Processing / Shipped / Delivered / Cancelled), select "Date range", кнопка "Reset filters".
3. **DataTable**, столбцы:
    - Order # (кликабельно → `/orders/:code`)
    - Customer (имя клиента/контрагента)
    - Manager (кто ведёт клиента — актуально для Operator/Dept Head, у Manager этой колонки может не быть, так как всегда "я")
    - Status (StatusBadge)
    - Total amount
    - Date placed
    - Branch/точка (если у пользователя видимость больше одной точки — Director/SB)
4. Пагинация снизу таблицы.

## Данные для примера (моковые строки)

Минимум 6-8 строк с разными статусами, разными клиентами и разными менеджерами (чтобы показать, что Operator видит НЕСКОЛЬКО менеджеров своего отдела одновременно).

## Состояния

- EmptyState, если фильтры ничего не нашли — "No orders match your filters" + кнопка "Reset filters".

## Переходы

Клик по строке/номеру заказа → `/orders/:code` (см. `03-order-detail.md`).
