# Общие конвенции для HTML-концептов страниц менеджерского портала mivend

> Этот файл описывает общий стиль, терминологию и переиспользуемые паттерны интерфейса для **всех** страниц портала. Если генерируешь HTML для конкретной страницы — прочитай сначала этот файл, потом файл самой страницы. Полный архитектурный контекст (права доступа, approval workflow, роли) — в `docs/ai/manager-portal-concept.md`, но для генерации HTML одной страницы обычно достаточно этого файла + файла страницы.

## Что это за продукт

Внутренний B2B backoffice-портал для сотрудников дистрибьюторской компании (не для конечных клиентов). Полностью заменяет Vendure Admin UI для операционной работы — заказы, клиенты, товары, цены, скидки, согласования. Пользователи — операторы, менеджеры, руководители отделов, генеральный директор, служба безопасности, администратор портала.

## Визуальный стиль

- **Плотный, деловой B2B-backoffice**, не consumer-приложение. Приоритет — плотность полезной информации на экране, не воздух и крупные акценты.
- Светлая тема по умолчанию, нейтральная палитра (серые/белые фоны, один акцентный цвет для первичных действий и статусов).
- Таблицы — основной способ показа списков (заказы, клиенты, документы), не карточные грид-сетки (это backoffice, не каталог).
- Шрифт без засечек, стандартный системный стек.
- Все интерфейсные подписи — **на английском** (проект англоязычный внутри, см. общие правила проекта), даже если сама компания русскоязычная.

## Общая структура layout (одинаковая на всех страницах)

```
┌─────────────────────────────────────────────────────────┐
│ Топ-бар: логотип "mivend" | имя текущего пользователя    │
│ (кликабельно → `/profile`), его роль (бейдж),            │
│          подразделение/филиал | выход                    │
├───────────┬─────────────────────────────────────────────┤
│           │  Хлебные крошки / заголовок страницы         │
│  Левое    │  ────────────────────────────────────────    │
│  меню     │                                               │
│  (см.     │  Контент страницы                            │
│  ниже)    │                                               │
│           │                                               │
└───────────┴─────────────────────────────────────────────┘
```

**Левое меню** (пункты, видимость зависит от прав роли — см. файл конкретной страницы):

- Dashboard
- Orders (включает кнопку "New order" → `/orders/new` — основная повседневная работа Оператора)
- Customers
- Catalog
- Discounts
- Approvals (с бейджем-счётчиком непрочитанных/ожидающих заявок, если есть)
- Documents
- Team
- Settings (видно не всем — только Администратору портала)

**Важно: в меню нет пункта "Pricing".** Корректировка цены/скидки по конкретному заказу — не отдельный раздел, а встроенный виджет прямо в строке товара на `02b-order-create.md`/`03-order-detail.md`. Это осознанное решение: разовая корректировка имеет смысл только в контексте уже открытого заказа.

## Роли (используются как метки на многих экранах)

| Роль                                               | Бейдж-цвет (условно) |
| -------------------------------------------------- | -------------------- |
| Operator (Оператор)                                | серый                |

## Переиспользуемые компоненты (упоминаются в файлах страниц)

- **StatusBadge** — цветная пилюля-бейдж для статусов (заказ, документ, заявка на согласование). Примеры значений: `Pending`, `Approved`, `Rejected`, `Ready`, `Expired`, `Expiring soon`.
- **DataTable** — плотная таблица со столбцами, сортировкой по клику на заголовок, пагинацией снизу, чекбоксами слева при массовых действиях.
- **FilterBar** — горизонтальная панель над таблицей: текстовый поиск + несколько select/dropdown фильтров + кнопка "Reset".
- **ApprovalStepper** — горизонтальная полоска шагов согласования (см. `approval-detail.md`) — кружки-этапы, соединённые линией, текущий шаг подсвечен, пройденные — галочкой, эскалированные — отдельной иконкой.
- **EmptyState** — для пустых списков: иконка + короткий текст + (опционально) кнопка действия.
- **Modal** — стандартное модальное окно для подтверждений и коротких форм (не для полноценных страниц).
- **Tooltip** — короткая подсказка при наведении (например, объяснение почему кнопка недоступна).

## Правила видимости данных (важно учитывать в моках/примерах на каждой странице)

Почти везде данные фильтруются по одной из схем:

- **own** — только то, что принадлежит текущему пользователю (свои клиенты у Менеджера).
- **department** — всё в рамках отдела текущего пользователя (Оператор, Руководитель отдела).
- **all** — вся компания (Ген. директор, СБ).

Когда описываешь моковые данные для страницы — учитывай, под какой ролью показан пример, и не показывай данные, которые эта роль не должна видеть (например, менеджер никогда не видит поле "предельная цена").

## Общая терминология (использовать точно эти слова в UI-текстах)

| Русский термин (для справки) | Английский UI-текст                                     |
| ---------------------------- | ------------------------------------------------------- |
| Согласование                 | Approval                                                |
| Заявка на согласование       | Approval request                                        |
| Установка скидки             | Discount grant                                          |
| Точечная корректировка цены  | Price adjustment                                        |
| Предельная цена              | Floor price (скрыто от Manager/Sales, см. `pricing.md`) |
| Эскалация                    | Escalate                                                |
| Продление                    | Renewal                                                 |
| Обоснование                  | Justification                                           |

## Технический формат вывода

Генерируй **самодостаточный статический HTML** (инлайн CSS или `<style>` в `<head>`, без внешних зависимостей/CDN) — это черновой визуальный концепт для обсуждения с заказчиком, не рабочий Vue-компонент. Один HTML-файл на страницу. Можно использовать моковые/примерные данные прямо в разметке.
