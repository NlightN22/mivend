# Страница: Order detail (`/orders/:code`)

> Прочитай сначала `00-shared-conventions.md`.

## Назначение

Детальный просмотр одного заказа — состав, клиент, статус, история, документы.

## Кто видит

Тот, кто вправе видеть этот заказ по правилам видимости из `02-orders-list.md` (own/department/all). На уровне HTML-концепта это не влияет на структуру страницы — просто не показывай элементы управления, которых нет ни у кого (см. "Действия" ниже).

## Структура контента

1. Хлебная крошка: "Orders / {Order #}".
2. Заголовок: номер заказа + StatusBadge статуса + дата размещения.
3. Блок "Customer" (карточка сбоку или сверху): имя клиента/контрагента, ИНН, ответственный менеджер, ссылка "View customer" → `/customers/:id`.
4. Таблица товарных позиций: SKU, название, кол-во, цена за единицу, скидка/наценка (если применена — с пометкой откуда: "self-service" или ссылка на заявку согласования, если применена через approval), сумма по строке, **колонка "Adjust"** с иконкой/ссылкой "Adjust price" у каждой строки (тот же виджет корректировки, что описан в `02b-order-create.md` — если заказ ещё редактируемый, т.е. не отгружен/не закрыт; для уже отгруженных заказов эта колонка не показывается вообще, только исторические факты корректировок).
5. Итоговый блок: подытог, скидка, доставка, итого к оплате.
6. Блок "Related documents": короткий список — счёт/договор/акт для этого клиента, каждый со ссылкой на `/documents` (или напрямую на скачивание).
7. Если по этому заказу была точечная корректировка цены через согласование — блок "Price adjustment history": одна строка со статусом заявки (StatusBadge) и ссылкой на `/approvals/:id`.

## Действия (кнопки, зависят от роли — покажи все для полноты концепта, подпиши в комментарии кто может)

- "Adjust price" по строке — см. п.4 выше; переиспользуй ровно тот же виджет (индикатор self-service/approval, скрытая floor price, обязательное обоснование при выходе за лимит), что в `02b-order-create.md` — **не делай отдельную страницу для этого**, это ключевое архитектурное решение (корректировка цены существует только в контексте открытого заказа, не как отдельный раздел меню).
- "Generate invoice" / "Generate contract" — если применимо (обычно уже происходит автоматически для счёта, договор — по запросу).

## Состояния

Если заказ не найден — простая страница-заглушка "Order not found" со ссылкой назад на `/orders`.
