# Страница: Approval request detail (`/approvals/:id`)

> Прочитай сначала `00-shared-conventions.md`. Это самая содержательная страница концепта — approval workflow — не упрощай.

## Назначение

Детальный экран одной заявки на согласование — что согласовывается, история шагов, действия "Approve"/"Reject"/"Escalate" для текущего согласующего.

## Структура контента

1. Хлебная крошка: "Approvals / Request #{id}".
2. Заголовок: тип заявки (например "Discount grant renewal") + StatusBadge общего статуса (Pending / Approved / Rejected).
3. **ApprovalStepper** — горизонтальная полоса шагов согласования, обязательный ключевой элемент:
    ```
    ● Sales Dept Head  ──  ● Purchasing Dept Head  ──  ○ General Director
    (approved,               (текущий шаг,               (ещё не дошло)
     зелёная галочка,         подсвечен синим/
     подпись "by Ivanov,      акцентным цветом)
     12 Jul, comment: ...")
    ```
    Для каждого пройденного шага — кто принял решение, дата, комментарий (если был). Текущий шаг — визуально выделен. Если по шагу была эскалация — вместо обычной подписи покажи "Escalated to {name} by {initiator}" с отдельной иконкой (не той же, что обычное согласование).
4. Блок "Request details" — карточка с данными самой заявки (зависит от типа):
    - Для `discountGrantApproval`: клиент, товарная группа, %, период действия, обоснование, и (если это продление) — блок "Supersedes: {previous discount ref}" со ссылкой/раскрывающимся списком истории предыдущих версий этой же скидки.
    - Для `priceAdjustmentApproval`: клиент, заказ, величина корректировки, обоснование.
5. Если текущий шаг закреплён за пользователем, открывшим страницу — блок действий внизу:
    - Textarea "Comment" (опционально для approve, обязательно для reject).
    - Кнопка "Approve" (зелёная), кнопка "Reject" (красная), кнопка-ссылка помельче "Escalate to..." (открывает select со списком ролей из заранее заданного `escalatesTo` для этого шага — **не свободный выбор человека**, только из ограниченного списка).
6. Если заявка уже завершена (Approved/Rejected) — блок действий не показывается, вместо него — просто финальная плашка с итогом ("Approved by General Director on 15 Jul").

## Состояния

- Заявка в процессе — степпер с частично пройденными шагами, блок действий виден.
- Заявка завершена (approved/rejected) — весь степпер закрашен/помечен, блок действий скрыт, финальная плашка.
- Обязательно сделай **два варианта HTML** или чётко покажи оба состояния в одном файле как раздельные секции с подписями "State A: pending my decision" / "State B: completed" — это ключевая механика экрана, стоит показать обе.
