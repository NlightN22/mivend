# Страница: Create order (`/orders/new`)

> Прочитай сначала `00-shared-conventions.md`. **Это одна из главных страниц всего портала** — основная повседневная работа Оператора: клиент звонит/пишет, оператор вручную забивает его заказ. Не второстепенный экран, продумай внимательно.

## Назначение

Полноценная страница создания заказа от лица клиента сотрудником компании (не сам клиент оформляет — это делает Оператор/Менеджер по его поручению, например по телефону). По духу похожа на checkout в клиентском storefront, но с точки зрения сотрудника: сначала выбирается клиент, дальше видно именно ЕГО цены/условия.

## Кто пользуется

Operator (основной сценарий, самый частый пользователь), Manager (для своих клиентов).

## Структура контента (пошагово сверху вниз на одной странице — не мастер с шагами, всё видно сразу, как в реальных backoffice-системах ввода заказов)

1. Заголовок "New Order".
2. **Блок "Customer"** (сверху, всегда виден): поле поиска клиента с автодополнением (по названию компании/ИНН) — до выбора клиента остальная форма неактивна/скрыта. После выбора — компактная карточка с именем клиента, кредитным лимитом/балансом, применяемым прайс-типом (Retail/Wholesale).
3. **Блок "Items"** — основная часть:
    - Поле поиска товара (по названию/SKU/OEM-коду/VIN — то же универсальное поле, что на `/catalog`) с автодополнением → кнопка "Add" добавляет строку в таблицу ниже. Это часто используемый сценарий телефонного заказа: клиент диктует VIN или номер детали с упаковки, а не точное название.
    - Таблица добавленных строк: SKU, название, кол-во (редактируемое число), цена за единицу (уже под прайс-тип выбранного клиента), **колонка "Adjust"** — маленькая иконка/ссылка "Adjust price" у каждой строки (см. ниже), сумма по строке, кнопка удаления строки.
    - **Виджет корректировки цены по строке** (открывается по клику "Adjust price", можно как разворачивающаяся секция прямо под строкой или как popover) — то же самое, что было бы отдельной страницей `/pricing`, но теперь встроено сюда:
        - Поле "Adjustment" — скидка (отрицательное) или наценка (положительное).
        - Индикатор результата: зелёный "✓ Within self-service limit — applies immediately" ИЛИ оранжевый "⚠ Below floor price — requires approval, order will be saved as draft pending approval".
        - Поле "Justification" (обязательно только во втором случае).
        - **Важно (конфиденциальность)**: как и в исходном описании — сотрудник никогда не видит числовое значение floor price, только результат проверки. Не выводи это число в HTML для роли Operator/Manager.
4. **Блок "Delivery & Payment"**: select "Trading point / delivery address", select "Payment method" (Online / Deferred / Invoice — переиспользуй логику из storefront checkout, см. референс-скриншоты).
5. Итоговая панель снизу (можно закреплённая/sticky): подытог, скидки суммарно, итого → кнопка **"Place order"** (если ни одна строка не требует согласования) или **"Save as draft & submit for approval"** (если хотя бы одна строка вне лимита — текст кнопки должен явно показывать, что произойдёт).

## Состояния

- До выбора клиента — блок Items недоступен/затемнён с подсказкой "Select a customer first".
- Если хотя бы одна строка требует согласования — итоговая кнопка меняет текст и рядом появляется предупреждение "This order includes a price adjustment pending approval — it won't ship until approved."
- Пустая таблица товаров — просто пусто, без специального EmptyState (это нормальное промежуточное состояние заполнения формы).

## После сохранения

Переход на `/orders/:code` только что созданного заказа (см. `03-order-detail.md`) — там будет видна ссылка на заявку согласования, если она была создана.
